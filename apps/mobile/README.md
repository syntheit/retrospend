# Retrospend mobile

One Expo app for iPhone, iPad and Android. `ios/` and `android/` are generated by `expo prebuild` and never committed.

## Build

### Android

From the repo root on harbor, after `pnpm install --frozen-lockfile`:

```sh
nix develop .#android -c bash apps/mobile/scripts/android-debug.sh
```

### iOS (on the Mac mini)

iOS builds run on the Mac mini (`ssh mini`). From the repo root on harbor:

```sh
bash apps/mobile/scripts/ios-build.sh          # all: device build, simulator run, install on the iPhone
bash apps/mobile/scripts/ios-build.sh device   # iPhone only
bash apps/mobile/scripts/ios-build.sh simulator
```

What it does:
1. Copies the checkout to `mini:~/rs-ios/retrospend` with rsync. Git data, `node_modules`, env files, keys and build output stay behind.
2. On the mini (`scripts/ios-mini.sh`): takes Node from the nixpkgs pinned in `flake.lock` (the mini's own Node 24.16 breaks Expo's bundle write with EBADF), installs the app's workspace with the repo's pinned pnpm through corepack, runs `expo prebuild -p ios --clean`, then `pod install`. Prebuild moves the app to the UIScene life cycle (`plugins/with-ios-scene-lifecycle.js`), which apps built with the iOS 27 SDK need to launch.
3. Builds Debug with `xcodebuild`. A production JS bundle is embedded (`EX_UPDATES_NATIVE_DEBUG=1` at pod install), so the app starts without Metro; a dev bundle without Metro fails at startup.
4. Device: signs for the iPhone, installs it with `xcrun devicectl device install app` and launches it once.
5. Simulator: builds for a "Retrospend iPhone 17" simulator on the newest iOS runtime that has an iPhone 17 (created if missing; today iOS 27.0, since the iOS 27.1 runtime only runs iPhone Duo), boots it, takes a screenshot and shuts it down. The screenshot lands in `docs/ui-overhaul/impl/shots/ios/` on harbor.

Logs stay on the mini in `~/rs-ios/logs/`, with the API key's values scrubbed. DerivedData is in `~/rs-ios/DerivedData`.

#### Signing

- Team `6NHZWHQX37` (Daniel Miller), set as `ios.appleTeamId` in `app.config.ts`. Bundle id `app.retrospend`.
- Xcode automatic signing (Apple Development certificate, the Xcode-managed "iOS Team Provisioning Profile: *"), driven by the App Store Connect API key in `~/.appstoreconnect/env` on the mini (`ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_KEY_PATH`). No Apple ID login.
- `scripts/ios-signing.sh` requests the certificate and registers the phone through the API, then keeps the identity in `~/Library/Keychains/retrospend-signing.keychain-db`, unlocked with a random password in `~/rs-ios/signing/keychain.pass` (mode 600, never leaves the mini). Over ssh the login keychain is locked, so Xcode cannot store a new key there itself. Xcode then only creates the profile (`-allowProvisioningUpdates`).
- The build runs through `sudo launchctl asuser`, inside the logged-in user's session: a plain ssh session has no per-user security services and codesign fails with `errSecInternalComponent`. Someone must be logged in on the mini.
- The API key never leaves the mini and is never printed; xcodebuild logs are scrubbed of its id, issuer and path.

#### On the phone

- Developer Mode on. Install works on a locked phone; launch needs it unlocked, so a locked phone ends the run with "device was not, or could not be, unlocked" and the app is already installed.
- First install of a new developer: if iOS refuses to open the app, go to Settings, General, VPN & Device Management, pick the developer app entry and tap Trust.

#### Requirements on the mini

Xcode with an iOS simulator runtime, Nix (for Node), and CocoaPods (the script installs it with Homebrew when missing).

## Install and update without a cable

Both channels number builds with the commit count (`RETROSPEND_BUILD_NUMBER` in `app.config.ts`), so each commit that ships is newer than the last.

### Android: private F-Droid repo "Retrospend dev"

On harbor, `retrospend-fdroid-release` (a NixOS command, `hosts/harbor/retrospend-fdroid.nix` in `~/nix`) builds, signs and publishes the main checkout. It is a wrapper around:

```sh
export FDROID_DIR=/var/lib/retrospend-fdroid    # repo working dir, created on first run, NOT in git
export KEYSTORE_FILE=... KEYSTORE_PASSWORD_FILE=... KEY_PASSWORD_FILE=... KEY_ALIAS=retrospend
nix develop .#android -c bash apps/mobile/scripts/android-release.sh
```

What it does: `expo prebuild`, Gradle `assembleRelease` (arm64-v8a only; `RETROSPEND_ABIS` to change), signed with the app key by `plugins/with-android-release-signing.js` (the key and passwords come from the environment and never enter the generated project), the Google-free check, `apksigner verify`, then `fdroid update`. The first run also creates the repo's own signing key (`repo-keystore.p12`, separate from the app key) and `config.yml` in `$FDROID_DIR`.

- Repo: `https://fdroid.retrospend.app/repo` (override with `FDROID_REPO_URL` before the first run), nginx on `127.0.0.1:1999`, Basic auth (user `daniel`), served through the harbor tunnel. It is a separate host because `dev.retrospend.app` is the Next.js container.
- Phones: Droid-ify or F-Droid, Repositories, add the URL, enter the Basic-auth user and password. Check the repo fingerprint the script prints. Later releases arrive as updates.
- Back up the app key. Losing it means uninstalling the app on every phone to install a differently signed one. The repo key lives in `$FDROID_DIR`; losing it means re-adding the repo on every phone.

### iOS: TestFlight

```sh
bash apps/mobile/scripts/ios-testflight.sh
```

From harbor, like `ios-build.sh`. It takes the simulator lock on the mini, copies the checkout to `~/rs-ios-plus/retrospend`, prebuilds, archives Release (production JS embedded), exports an `.ipa` for App Store Connect (`~/rs-ios-plus/archive/export`) and uploads it with `altool` and the API key in `~/.appstoreconnect/env`. The key never leaves the mini and logs are scrubbed. It stops if the mini has under 8 GB free.

- Needs the app record for `app.retrospend` in App Store Connect and an API key with the role App Manager or Admin. Both are web UI steps; without the record the script still ends with a signed `.ipa` and says so.
- `ITSAppUsesNonExemptEncryption` is false (`app.config.ts`), so builds skip the export compliance question.
- Install: TestFlight app on the iPhone and iPad, accept the internal tester invite. New builds update from there.

## Known issues

- iOS 26.x (seen on 26.5): with the detached "+" in the tab bar, the four destination titles are truncated ("Acti...", "Peo..."). It is react-native-screens issue 5015; iOS 27 is not affected. Accepted for now.
- Hardware keyboard (iOS): Cmd+N opens the composer, Cmd+F focuses the search bar of the screen in front. React Native has no key command API and Expo UI no SwiftUI `keyboardShortcut`, so `modules/hardware-keys` (a local Expo module, picked up by prebuild) puts UIKeyCommands on the root view controller. Android has no hardware shortcuts yet.
- iPhone: while a search field has focus the keyboard covers the tab bar, and with it the system "+". That is stock iOS behavior and is kept (owner decision); the lists dismiss the keyboard on drag.
- iPad: the sidebar floats over the content, so `Screen` and `ListDetail` use the native `SafeAreaView` to start after it. A `Screen` inside a list-detail pane is cleared by the pair and must not wrap again.
